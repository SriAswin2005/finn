# Billing-disabled Gemini and shared model policy

Current November2,2026. Both hosted workflows are enabled using the already-approved original key; no new credential/account action is required. Never enable billing/paid fallback or publish credentials. `.env.example` remains safe/off by default for new checkouts.

## Models are configuration

`src/config/model-policy.json` owns IDs, disjoint roles, per-model limits/thinking and optional explicit `researchOrder`. `text-model-catalog.json` contains additional inventory-only text IDs, not invocation permission. Runtime defaults/order contain no generation-specific IDs. Future replacements require updating approved model IDs/quotas/roles/order and the non-secret selected inventory; unknown quotas/free eligibility are never inferred from model listing alone. Old attempts retain original workflow/model labels; accepted notes are not regenerated by upgrades.

Aggregate1040/day,520/workflow and all retries inside the same totals are ceilings; lifetime3 remains. Per-model Pacific daily reset and conservative aggregate/workflow rolling24h caps both apply. Provider quota/shared project holds remain authoritative; no key rotation or resetting history.

Research uses explicit configured priority when provided, otherwise generic family/parameter-size order. It skips zero-call model-only capacity blocks, makes at most3 actual attempts within65seconds (40seconds each maximum), and stops on project/auth/configuration errors. Shared stable evidenceHash+prompt identity preserves legacy model-list cache/lease/rejection/attempt aliases through routing changes. Only new exact supported answers are saved; source-reviewed exact-evidence legacy notes may survive prompt changes after validation.

Push chooses suitable capability from configuration, one network attempt per scheduled invocation (60seconds). Fresh ordinary work prefers Lite; retries prefer an unused suitable model, including stronger Push capacity. Complex work never downgrades. Project/auth holds still stop all rotation. Its opt-in single whole-draft correction escalates ordinary validation failure to complex capacity with the same evidence and source diagnostic/previous untrusted draft. Unsupported first/second output is not published; no third automatic correction. All attempts/timeouts/retries count; unavailable complex capacity waits rather than downgrading. Rejected raw drafts and source diagnostics remain server-side. Research also retains bounded rejected visible output with model/prompt/finish/reservation/error; it never automatically regenerates rejected requests.

## Operations

Existing local/hosted workers use canonical Neon via ignored server-only DATABASE_URL. `npm start` loads ignored `.env`; `npm run configure:ai` accepts the key through hidden local input and confirmed billing-disabled status, preserves unrelated settings and makes0 calls. Existing checkout is initialized. NEVER delete quota or run init to create a fresh allowance; new environments must reconcile real history first.

Prefix commands with `node --env-file=.env scripts/push.js`:

| Command | Effect |
| --- | --- |
|status |Read shared status,0 model calls |
|collect |Bounded source refresh/catch-up,0 model calls |
|tick |One collection, up to2 document steps, up to5 zero-call analysis skips and at most1 actual model request |
|policy |Audit previous/new approved configuration; preserve attempts/provider holds; recheck only local-allocation waits |
|retry KEY REVIEW_REASON [--complex] |Reviewed failed-job recovery below lifetime3, reason20–500characters; no refund/reset |
|revalidate KEY REVIEW_REASON |Whole unchanged structured draft through current guards, original reservation required,0 calls/partial curation |

Production flags: FINN_AI_FREE_TIER_CONFIRMED=true, FINN_AI_CACHE_ONLY=false, FINN_AI_LIVE_ENABLED=true, FINN_PUSH_ENABLED=true, FINN_PUSH_HOSTED_APPROVED=true, FINN_PUSH_VALIDATION_REPAIR=true. FINN_GEMINI_MODELS lists the four approved configured IDs. Credentials stay server-only. FINN_MODEL_POLICY_JSON can override configuration, but persisted shared policy must be deliberately audited/applied too.

Evaluations use an assigned model only: FINN_RESEARCH_EVALUATION_MODEL isolates one Research model; FINN_PUSH_EVALUATION_MODEL applies only to explicit captured Push evaluation. Neither bypasses quotas or promotes captures into Latest. Normal workers exclude captures. Do not casually run evaluation scripts/requeue exhausted jobs.

App opens/navigation/source Refresh/saved answer reuse make0 model calls. Missing/corrupt/unwritable quota fails closed; source evidence remains available. Public document excerpts and explicit Research questions go to Google; credentials/preferences/portfolio account data do not. Numeric/name/metric/scope/condition validation reduces known errors, but does not guarantee omission-free semantic quality.
