# Working on FINN

Read [AGENTS.md](AGENTS.md), [HANDOFF.md](HANDOFF.md), [current progress](PROGRESS.md), [current issues](docs/ISSUES.md) and the [standing working agreement](docs/WORKING_AGREEMENT.md) before changing the project. These preserve the user's instructions when the original chat is unavailable.

Use the handoff's task/file map to read only the relevant slice. Keep code and affected status/issue/verification documents synchronized immediately, including tiny changes. Verify each coherent checkpoint, commit with one or two concrete sentences describing the actual change, and push to the approved private origin. Do not leave documentation or Git preservation for a later reminder.

Preserve current user work, evidence/financial correctness boundaries, free-tier caps and permission limits. Report failures promptly and distinguish verified, incomplete and untested behavior. Detailed maintenance responsibilities, examples and approval boundaries are in the working agreement; follow them rather than inventing a different workflow.
